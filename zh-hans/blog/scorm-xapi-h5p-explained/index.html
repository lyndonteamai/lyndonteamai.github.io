SCORM、xAPI、H5P 怎样选？香港电子学习内容标准实用对照

SCORM 1.2、SCORM 2004、xAPI 与 H5P 的实务比较——各标准存储什么、何时会失效，以及 Drupal LMS 怎样同时支持全部三种。

本文目录

  1. 先讲结论
  2. SCORM：封装标准
  3. xAPI：陈述标准
  4. H5P：内容创作标准
  5. 按内容类型选择
  6. 香港项目常见的坑

重点数据

SCORM、xAPI 定 H5P？
三者都用，分别解决不同问题。SCORM 负责把课程打包封装，xAPI 记录封装以外的学习，H5P 是可在浏览器内创作互动内容的格式。
SCORM 1.2 定 SCORM 2004？
旧有内容库与最广的创作工具相容性用 1.2；需要完成状态、更丰富排序与互动层级作答数据则用 2004。
Drupal LMS 内建 LRS 吗？
LMS Xapi 内建一个极简 LRS，用于存储分数与活动状态——足以在自己基建内收集与报表，但不是具备长期分析的完整商业 LRS。
H5P 创作要付费吗？
不用。H5P 在浏览器内创作与编辑，不需购买桌面创作工具授权。
香港最常见的错误是什么？
收集 xAPI 陈述却没有决定存放在哪里、保留多久、谁可以读取——在PDPO 下构成个人数据风险。
这篇文章适合谁看？
需要选择内容标准的香港电子学习团队与人力资源内容负责人。

先讲结论

这三者不是互相竞争的产品，而是解决不同问题；一个认真的香港电子学习体系会同时用到三者。SCORM 负责把课程打包封装、xAPI 记录学员在封装课程之外做过什么、H5P 则是让互动内容直接写在页面里的创作格式。

一句话版本

SCORM ＝「课程在这里，告诉我分数。」xAPI ＝「学员实际做过的事情在这里。」H5P ＝「这是一个我可以在浏览器里编辑的互动内容。」

SCORM：封装标准

SCORM 是封装电子学习内容的规格。一个 SCORM 封装是一个 zip 档，内含一个 manifest 与素材。LMS 启动它时，内容在一个由 LMS 公开的 API 里执行，然后把完成情况、分数与续读位元回报。

商业上有两个版本值得留意：

  • SCORM 1.2——长期的预设值。全球创作工具相容性最广。数据模型有限：基本上只有完成、分数与续读状态。
  • SCORM 2004——更丰富的排序控制、多个学习目标、完成状态、互动数据，以及正确／错误作答明细。需要创作工具与 LMS 都有相应支持。

对正在迁移既有内容库的香港机构而言，SCORM 相容性正是你带得走旧资产的原因。这也是它在每一张认真的供应商比较表上都出现的原因，包括 Opigno Enterprise——它明确列出支持 SCORM 1.2 及 2004，并支持 Articulate Storyline 与 Adobe Captivate。

SCORM 吃力的地方是封装边界以外的任何场景。若学习发生在工作场所、会议之中，或横跨多个系统，SCORM 没有地方存放证据。xAPI 就是为了填补这个缺口而设计的。

xAPI：陈述标准

xAPI（又称 Tin Can API）记录的是陈述（statement）：主体、动词、客体、情境，并带时间戳。一条陈述就是一件与学习有关事件的小型结构化记录。

{
  "actor":  { "name": "Employee 4711" },
  "verb":   { "id": "http://adlnet.gov/expapi/verbs/completed",
              "display": { "en-US": "completed" } },
  "object": { "id": "https://lms.example/xapi/courses/safety-101",
              "definition": { "name": { "en-US": "Workplace Safety 101" } } },
  "result": { "completion": true, "success": true },
  "context": { "contextActivities": { "parent": [ /* course */ ] } },
  "timestamp": "2026-10-12T09:41:07Z"
}

架构上最重要的一点：xAPI 陈述是送往 LRS（Learning Record Store，学习记录库），而不只是送往 LMS。这把「记录学习」与「交付课程」解耦——当学习本身不是课程形状时，这正是你需要的。

Drupal LMS 提供 LMS Xapi，包含一个 activity 答案插件、一个适用于任何实体类型的字段格式化器、xAPI 封装导入支持（例如从 Articulate 360 导入），以及项目所描述的一个极简 LRS，用于存储分数与活动状态。老实说明范围：极简 LRS 足以在自己基建内做陈述收集与报表，但它不是具备长期分析的完整商业 LRS；如果你需要，我们会另行报价。

Drupal LMS 内有 xapi_tincan 这个 activity 类型，因此 xAPI 内容可以像普通 activity 一样在课程内使用。

H5P：内容创作标准

H5P 是另一个类别：一套开源互动内容类型库，在浏览器内创作与编辑，涵盖互动视频、测验、分岔情境、演示文稿、拖放、时间线、闪卡等等。

对学校而言，H5P 可谓三者之中杠杆最高的一个，因为它去掉了创作工具的授权成本。教师自己制作互动内容，而毋须按人购买桌面创作工具。对企业培训而言，它是把知识检测直接嵌进课节里最快的路径，而不是另外贴上一张练习纸。

Drupal LMS 通过 LMS H5P集成，并接入 Drupal H5P 开放整个内容库。留意一个值得记住的命名分别：Drupal LMS H5P 是 LMS 集成模块；Drupal H5P 是底层内容框架。

香港项目常见的坑

SCORM 2004 但创作工具不支持

内容宣告 2004 排序控制，但创作工具实际只输出 1.2 语意。课程可以启动，但续读数据与目标追踪的行为会出意外。要在购买时检查创作工具版本，不是在上载时。

收集 xAPI 陈述却没有 LRS 计划

收集陈述但没有决定存放在哪里、保留多久、谁可以读取，就等于在 PDPO 下制造个人数据风险。要在写入第一条陈述之前就定好保留期与访问权限，而不是之后才补。

把 H5P 当成教学设计的替代品

一段互动视频不是一门课。H5P 内容背后仍然需要学习目标、排序与评估计划。这正是我们教材开发业务存在的原因——平台令制作内容变便宜，但仍然需要有人去设计它。

坦白提醒

没有任何标准能解决真正问题：没有学习目标的内容，只会产生活动数据，而不会产生能力转变。标准能搬动数据，但搬不动结果。

如果你的内容策略是「我们统一用 SCORM 2004，什么都会互通」，那么你只解决了封装这一件事。

关于内容标准的问题

应该统一采用哪一个标准？

视内容类型，诚实的答案是您最终会用到多于一个。SCORM 1.2同2004用于封装式、可评估、追踪完成情况的电子学习；H5P用于浏览器内制作的互动内容；xAPI用于LMS以外活动的细致陈述，包括真实工作场景。文章会把内容类型对应到标准。

如果转平台，SCORM内容还能用吗？

可以——标准的意义正在于此。SCORM套件可以携带，只要两个平台都支持。所以即使对现有平台没有怀疑，我们仍然建议采用标准化内容同YAML课程套件：这是令日后迁移保持低成本的关键。

xAPI包含纪录存储库吗？

包含。LMS Xapi提供xAPI套件支持，并附一个最小化的LRS用来存储分数与活动状态。对多数香港机构而言，这已经足够起步；完整的LRS是另一个决定，也有其运行含意，我们会提供建议而不是让您预设地被导向某一个选择。

内容标准项目最常在哪里出问题？

最常见的失败，是在专利工具里制作内容，事后才发现导出路径有限或有损。其次是假设标准可以解决评估设计。文章会交代我们在香港项目见过的陷阱，包括在落实工具之前应该先核实什么。

商业编辑工具的内容可以迁移吗？

经常可以，但答案完全取决于该工具的导出路径。我们在界定范围时会对照您实际内容的样本核实，而不是只读说明文件。内容能干净导出的，通常可以转换；不能的，我们会告诉您应该转换、重建，还是原地保留。

正在迁移既有内容库？

给我们一个 SCORM 封装样本或一个 H5P 内容库，我们会告诉你哪些可以直接搬、哪些需要转换、哪些应该重新制作而不是迁移。
