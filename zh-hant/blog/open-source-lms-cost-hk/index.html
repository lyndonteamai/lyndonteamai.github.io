開源 LMS 在香港的真正成本

零授權費只是標題。真正的總擁有成本在主機、配置、整合、內容與維運。我們為香港機構誠實地拆解每一條成本線。

重點資料

授權費是多少？
HK$0，沒有按人收費，也沒有年度續約。
那實際要付甚麼錢？
主機、配置與客製、整合、內容開發，以及維運與支援。
開源一定更便宜嗎？
不一定。對約 40 名員工、培訓需求不大的機構，商業授權的總成本可能更低。開源的優勢會隨學員人數、既有的 Drupal 或 PHP 能力，以及擁有資料的策略價值而增強。
打平點怎樣判斷？
當同一期內省下的授權成本，大於主機、攤分後的配置、整合、內容、維運工時與升級工作量的總和。
有哪些隱藏成本？
退出成本、升級成本、技能成本、內部開發人力的機會成本，以及 PDPO 下的合規責任。
這篇文章適合誰看？
需要評估 LMS 授權的香港財務與採購團隊，以及需要一個誠實總成本數字的 HR 主管。

標題與附帶條件

這套說法很有吸引力：企業級學習平台、零授權費、無按人收費、無需年度續約、資料與代碼都歸你。對一間有 1,200 名學生的香港學區，或一間有 8,000 名員工的企業，這等於拿掉一項本來每年要六位數的開支。

然後採購問題就來了：如果授權是免費的，我們實際付錢買的是甚麼？這個問題問得對，而開源項目輸掉本該贏的生意，往往就是因為答錯了這題。

剩下的五條成本線

1. 主機與基建

一個生產環境的 LMS 需要數據庫、應用伺服器、物件儲存、備份與監控。本地機房意味着資本性硬件加上機櫃與電費；私有雲是月度帳單；託管主機也是月度帳單，但有人候命。在香港，中型部署的雲端支出通常主導整條營運成本。

2. 配置與客製

你不是在安裝一個產品，而是在建一個網站。Drupal 提供的是通用 CMS，Drupal LMS 提供的是模組。把它變成你的審批流程、你的報表組合、你的角色結構，是真實工作量。這通常是一次性成本中最大的一項。

3. 整合

每一個必須與 LMS 對話的系統——HRIS、身份供應商、Microsoft 365、Slack、記錄培訓開支的財務系統——都是一條獨立成本線，也帶獨立風險。整合愈多，總成本愈容易上升，時間表也愈長。

4. 內容

這是多數香港機構低估的一項。授權不會送來教材。H5P 創作是免費但需要設計；SCORM 製作需要創作工具與教學設計；三語內容會把工作量成倍放大。以三年為期，內容成本通常高於平台成本。

5. 維運與支援

總得有人運維：開用戶、維護課程、準備報表、平台升級、保安修補。如果這是現有 IT 團隊，就是人力成本；如果不是，就是一份託管服務合約。

供應商從不提的成本

隱藏成本實際意味着甚麼
退出成本專有平台在終止時可能需要資料抽取工作。GPL 平台不需要——但這個價值只有在你真正擁有數據庫時才會實現
升級成本商業供應商把大版本升級吸收在訂閱內。開源則把這份工作每年、永久地轉移給你
技能成本Drupal 與 PHP 是主流技能，某些專有 LMS 技術棧不是。先確認你是要招聘還是要自己培訓
機會成本投入平台維護的內部開發人力，其機會成本從來沒有人計算
合規成本PDPO、審計證據與保留政策，無論平台由誰運維，都是你的責任

打平點在哪裏

一個比較「零授權平台」與「商業按人授權」的粗略模型：

年度授權成本（商業）
  = 授權人數 x 每人費用 x 年數

總擁有成本（開源）
  = 主機
  + 配置（一次性，攤分）
  + 整合（一次性）
  + 內容（持續）
  + 維運工時
  + 升級工作量

打平點：省下的授權成本
大於同一期內所有開源成本線的總和。

令人不舒服的觀察是：對一間只有 40 名員工、培訓需求不大的小型機構，一旦計入主機與維運，商業授權可能真的更便宜。開源的優勢會隨學員人數、你本身是否已有 Drupal 或 PHP 能力、以及擁有資料是否具策略價值而增強。

誠實的答案

如果沒有任何人向你銷售開源平台，要保持懷疑。一間只懂得講授權經濟的供應商，代表沒有想過另外五條成本線。

我們會對潛在客戶這樣說：授權確實免費，而剩下的工作確實要付錢。我們把主機、配置、整合、內容與支援分開報價，也會告訴你什麼時候商業平台對你的規模而言是更划算的經濟選擇。那種對話對我們的價值，遠高於一筆我們事後會後悔的生意。

甚麼時候開源是錯的選擇

你身邊沒有人能運維網絡平台。你需要合約形式的可用性與問責，而你無法自行交付。你重視「開箱即用」的確定性，多於重視擁有資料。在這些情況下，買商業產品，付錢買確定性。

授權是免費的。但決定仍然應該是對的。

關於開源LMS成本的問題

整體擁有成本裏面實際包括甚麼？

授權費以外有六項：託管與基建、部署與設定、資料與內容遷移、整合與客製開發、內容，以及持續的管理、培訓、技術支援與運作。任何沒有把這六項分開列出的數字，都不是整體擁有成本，只是穿了外衣的授權費。

打和點在哪裏？

視乎用戶人數、你們實際會用到平台多少，以及是否本身已有維運平台的技術能力。對於人數少、培訓需求輕的機構，一旦計入託管與管理，商業授權確實可以更便宜。開源的理據在規模擴大、已有Drupal或PHP能力，以及擁有資料本身具策略價值時才最強。

哪些成本最令人意外？

通常是三項：授權費與第一個使用者之間那段設定與流程工作；每年重複的管理工時；以及升級工作量——這一項大家常當作零，之後每十八個月就體驗一次。它們都不是迴避開源的理由，而是把範界定好才對的理由。

遷移成本通常大嗎？

視乎要保留多少歷史紀錄，以及有多少報表要繼續運作，而它經常是開源方案第一年預算裏最大的一條。SCORM、H5P或YAML的內容可以原生搬遷；專利內容同舊有報表才是費力所在——所以在任何承諾之前先做一次遷移評估，值得花那點時間。

政府資助計劃會改變計算嗎？

資助可以改變項目的實際成本，但評估是對具體建議書，不是對產品名稱，資格由資助機構決定。我們不會告訴您一定會獲批，也不會以資助計劃作為購買平台的理由。本網站討論的每一個計劃，都附有它當前的真實狀態。

想要一份有誠意的範圍報價？

告訴我們你的學員人數、現有系統和需要的報表。我們會在你決定之前逐項列明每一條成本線——如果商業授權對你更便宜，我們也會直接說。
