SCORM、xAPI、H5P 怎樣選？香港電子學習內容標準實用對照

SCORM 1.2、SCORM 2004、xAPI 與 H5P 的實務比較——各標準儲存甚麼、何時會失效，以及 Drupal LMS 怎樣同時支援全部三種。

  1. 先講結論
  2. SCORM：封裝標準
  3. xAPI：陳述標準
  4. H5P：內容創作標準
  5. 按內容類型選擇
  6. 香港項目常見的坑

重點資料

SCORM、xAPI 定 H5P？
三者都用，分別解決不同問題。SCORM 負責把課程打包封裝，xAPI 記錄封裝以外的學習，H5P 是可在瀏覽器內創作互動內容的格式。
SCORM 1.2 定 SCORM 2004？
舊有內容庫與最廣的創作工具相容性用 1.2；需要完成狀態、更豐富排序與互動層級作答數據則用 2004。
Drupal LMS 內建 LRS 嗎？
LMS Xapi 內建一個極簡 LRS，用於儲存分數與活動狀態——足以在自己基建內收集與報表，但不是具備長期分析的完整商業 LRS。
H5P 創作要付費嗎？
不用。H5P 在瀏覽器內創作與編輯，不需購買桌面創作工具授權。
香港最常見的錯誤是甚麼？
收集 xAPI 陳述卻沒有決定存放在哪裏、保留多久、誰可以讀取——在PDPO 下構成個人資料風險。
這篇文章適合誰看？
需要選擇內容標準的香港電子學習團隊與人力資源內容負責人。

先講結論

這三者不是互相競爭的產品，而是解決不同問題；一個認真的香港電子學習體系會同時用到三者。SCORM 負責把課程打包封裝、xAPI 記錄學員在封裝課程之外做過甚麼、H5P 則是讓互動內容直接寫在頁面裏的創作格式。

一句話版本

SCORM ＝「課程在這裏，告訴我分數。」xAPI ＝「學員實際做過的事情在這裏。」H5P ＝「這是一個我可以在瀏覽器裏編輯的互動內容。」

SCORM：封裝標準

SCORM 是封裝電子學習內容的規格。一個 SCORM 封裝是一個 zip 檔，內含一個 manifest 與素材。LMS 啟動它時，內容在一個由 LMS 公開的 API 裏執行，然後把完成情況、分數與續讀位元回報。

商業上有兩個版本值得留意：

  • SCORM 1.2——長期的預設值。全球創作工具相容性最廣。數據模型有限：基本上只有完成、分數與續讀狀態。
  • SCORM 2004——更豐富的排序控制、多個學習目標、完成狀態、互動數據，以及正確／錯誤作答明細。需要創作工具與 LMS 都有相應支援。

對正在遷移既有內容庫的香港機構而言，SCORM 相容性正是你帶得走舊資產的原因。這也是它在每一張認真的供應商比較表上都出現的原因，包括 Opigno Enterprise——它明確列出支援 SCORM 1.2 及 2004，並支援 Articulate Storyline 與 Adobe Captivate。

SCORM 吃力的地方是封裝邊界以外的任何場景。若學習發生在工作場所、會議之中，或橫跨多個系統，SCORM 沒有地方存放證據。xAPI 就是為了填補這個缺口而設計的。

xAPI：陳述標準

xAPI（又稱 Tin Can API）記錄的是陳述（statement）：主體、動詞、客體、情境，並帶時間戳。一條陳述就是一件與學習有關事件的小型結構化記錄。

{
  "actor":  { "name": "Employee 4711" },
  "verb":   { "id": "http://adlnet.gov/expapi/verbs/completed",
              "display": { "en-US": "completed" } },
  "object": { "id": "https://lms.example/xapi/courses/safety-101",
              "definition": { "name": { "en-US": "Workplace Safety 101" } } },
  "result": { "completion": true, "success": true },
  "context": { "contextActivities": { "parent": [ /* course */ ] } },
  "timestamp": "2026-10-12T09:41:07Z"
}

架構上最重要的一點：xAPI 陳述是送往 LRS（Learning Record Store，學習記錄庫），而不只是送往 LMS。這把「記錄學習」與「交付課程」解耦——當學習本身不是課程形狀時，這正是你需要的。

Drupal LMS 提供 LMS Xapi，包含一個 activity 答案外掛、一個適用於任何實體類型的欄位格式化器、xAPI 封裝匯入支援（例如從 Articulate 360 匯入），以及項目所描述的一個極簡 LRS，用於儲存分數與活動狀態。老實說明範圍：極簡 LRS 足以在自己基建內做陳述收集與報表，但它不是具備長期分析的完整商業 LRS；如果你需要，我們會另行報價。

Drupal LMS 內有 xapi_tincan 這個 activity 類型，因此 xAPI 內容可以像普通 activity 一樣在課程內使用。

H5P：內容創作標準

H5P 是另一個類別：一套開源互動內容類型庫，在瀏覽器內創作與編輯，涵蓋互動影片、測驗、分岔情境、簡報、拖放、時間線、閃卡等等。

對學校而言，H5P 可謂三者之中槓桿最高的一個，因為它去掉了創作工具的授權成本。教師自己製作互動內容，而毋須按人購買桌面創作工具。對企業培訓而言，它是把知識檢測直接嵌進課節裡最快的路徑，而不是另外貼上一張工作紙。

Drupal LMS 透過 LMS H5P整合，並接入 Drupal H5P 開放整個內容庫。留意一個值得記住的命名分別：Drupal LMS H5P 是 LMS 整合模組；Drupal H5P 是底層內容框架。

香港項目常見的坑

SCORM 2004 但創作工具不支援

內容宣告 2004 排序控制，但創作工具實際只輸出 1.2 語意。課程可以啟動，但續讀資料與目標追蹤的行為會出意外。要在購買時檢查創作工具版本，不是在上載時。

收集 xAPI 陳述卻沒有 LRS 計劃

收集陳述但沒有決定存放在哪裏、保留多久、誰可以讀取，就等於在 PDPO 下製造個人資料風險。要在寫入第一條陳述之前就定好保留期與存取權限，而不是之後才補。

把 H5P 當成教學設計的替代品

一段互動影片不是一門課。H5P 內容背後仍然需要學習目標、排序與評核計劃。這正是我們教材開發業務存在的原因——平台令製作內容變便宜，但仍然需要有人去設計它。

坦白提醒

沒有任何標準能解決真正問題：沒有學習目標的內容，只會產生活動數據，而不會產生能力轉變。標準能搬動數據，但搬不動結果。

如果你的內容策略是「我們統一用 SCORM 2004，甚麼都會互通」，那麼你只解決了封裝這一件事。

關於內容標準的問題

應該統一採用哪一個標準？

視乎內容類型，誠實的答案是您最終會用到多於一個。SCORM 1.2同2004用於封裝式、可評核、追蹤完成情況的電子學習；H5P用於瀏覽器內製作的互動內容；xAPI用於LMS以外活動的細緻陳述，包括真實工作場景。文章會把內容類型對應到標準。

如果轉平台，SCORM內容還能用嗎？

可以——標準的意義正在於此。SCORM套件可以攜帶，只要兩個平台都支援。所以即使對現有平台沒有懷疑，我們仍然建議採用標準化內容同YAML課程套件：這是令日後遷移保持低成本的關鍵。

xAPI包含紀錄儲存庫嗎？

包含。LMS Xapi提供xAPI套件支援，並附一個最小化的LRS用來儲存分數與活動狀態。對多數香港機構而言，這已經足夠起步；完整的LRS是另一個決定，也有其運作含意，我們會提供建議而不是讓您預設地被導向某一個選擇。

內容標準項目最常在哪裡出問題？

最常見的失敗，是在專利工具裏製作內容，事後才發現匯出路徑有限或有損。其次是假設標準可以解決評核設計。文章會交代我們在香港項目見過的陷阱，包括在落實工具之前應該先核實甚麼。

商業編輯工具的內容可以遷移嗎？

經常可以，但答案完全取決於該工具的匯出路徑。我們在界定範圍時會對照您實際內容的樣本核實，而不是只讀說明文件。內容能乾淨匯出的，通常可以轉換；不能的，我們會告訴您應該轉換、重建，還是原地保留。

正在遷移既有內容庫？

給我們一個 SCORM 封裝樣本或一個 H5P 內容庫，我們會告訴你哪些可以直接搬、哪些需要轉換、哪些應該重新製作而不是遷移。
